# 외부 레퍼런스: Nostr — 기판(substrate) 후보 검증

**Nostr** (Notes and Other Stuff Transmitted by Relays) 를 우리 시스템의 **③기판층**
([`../architecture-layers.md`](../architecture-layers.md)) 후보로 검증한다.

> ⚠️ 외부 기술 요약 + 우리 관점의 적합성 검증.

---

## 1. 개요

- **언제:** 개념은 2020~2021년(익명 개발자 *fiatjaf*). 2022-12 잭 도시의 비트코인
  기부(~14 BTC)로 부상, 2023 초 iOS 앱 *Damus* 출시로 대중화. 비교적 최근, 성장 중.
- **작동(비유):** 동네 게시판.
  - **🖊️ 도장(키):** 가입 없음. 앱이 내 키쌍을 만든다. 모든 글에 내 도장(서명)을
    찍는다 — 위조 불가.
  - **📝 쪽지(이벤트):** 글에 서명을 박는다. 글자 하나 바뀌면 서명이 깨져 들통.
  - **📮 게시판(릴레이):** 서명된 쪽지를 여러 릴레이에 붙인다. 상대가 접속하면
    릴레이에서 가져가 서명을 확인하고 읽는다.
- **핵심 3가지:** ① 내가 오프라인이어도 릴레이가 들고 있음(상시접속 불필요) ②
  릴레이는 위조 못 함(서명) — 단순 보관소 ③ 한 릴레이가 막아도 다른 릴레이로
  → 검열저항·이식성.

---

## 2. 우리 기판으로 본 적합성

### 잘 맞는 것
- **신원·서명·이식성·검열저항을 공짜로** 준다 → 설계 §2.2 "이식성 ↔ lock-in"
  긴장의 한 답. 이식성을 주되 해자는 ①시장층(평가·검증·네트워크효과)으로 옮긴다.
- **지식 노드를 서명된 이벤트로** 담을 수 있다: 커스텀 이벤트 종류(NIP/kind),
  부모 이벤트 참조로 트리(계승/포크) 구성, 작성자 = 도장.

### 못 푸는 것 (정직하게)
- **릴레이는 보관소일 뿐 계산을 안 한다.** 우리 핵심인 *집계 상태*(허브/권위 점수,
  스테이킹 원장, 검증 게이트, 배당)는 Nostr **밖의 인덱서/계산층**이 필요하다.
  → Nostr = 진실의 원천(서명된 기여)층, **평가·경제는 그 위 별도 신뢰층.**
- **①현실 접점(오라클·환전)을 안 푼다.** 신원·이식성(소유권)만 푼다. 측정의 정직,
  포인트→현실가치는 여전히 별도 과제.
- 포인트/결제는 게시판으로 안 된다 → *얇은 결제층*을 옆에 붙여야(사용자 직관과 일치).

### 트랙별 적용
- **MVP(B2B):** 보류. 사내는 폐쇄·권한·KPI 닻을 원한다 — 검열저항·공개·익명은 과함.
- **풀스펙(공개·이식성):** 유력. 검열저항·자기소유 지식. 이 트랙에서 계속 검증.

## 3. 스케치 — 지식 노드를 Nostr에 담는다면

```
[Nostr 이벤트 = 서명된 지식 노드]
  pubkey   = 작성자(도장)
  kind     = (커스텀) 지식 Q&A 노드
  tags     = ["e", 부모노드id, ...]   # 계승/포크 = 부모 참조
             ["t", 온톨로지/주제]
  content  = { question, answer, ... }
  sig      = 서명(위변조 불가)
        │
        ▼  (릴레이에 게시 — 보관·전파만)
[인덱서/계산층 (Nostr 밖, 우리 ①시장층)]
  서명 검증된 이벤트를 읽어 → 허브/권위 집계 · 스테이킹 원장 · 검증 게이트 · 배당
        │
        ▼
[얇은 결제층]  포인트↔현실가치 (B2B면 조직 보상 풀)
```

요지: **Nostr는 ③기판으로 채택 검토 가치가 크되, ①시장층(평가·경제·현실 닻)은
반드시 그 위에 별도로 얹어야 한다.**
