## 1. 글의 논지

- "지식그래프를 Graph DB·RDF·Cypher/SPARQL 같은 *기술*로 먼저 이해하지만, 본질은
  **AI가 따라갈 수 있는 관계의 길**을 만드는 것."
- 실무 질문은 단순 검색이 아니다: 엔티티·관계·속성·**출처(provenance)**·근거·
  최신성·권한이 함께 움직여야 한다.
- **5단계 구조:** ① 기초 모델링(무엇을 노드로?) ② 구조화(엔티티 추출 + **같은
  대상을 하나의 ID로 정규화** + provenance) ③ 검색·탐색(벡터 + 그래프 + 하이브리드
  → "비슷한 문서" 아닌 "연결된 근거") ④ AI 응용(GraphRAG·근거 답변) ⑤ 운영
  거버넌스(권한·최신성·**신뢰도 점수**·감사 로그).
- 결론: "문서 검색은 답을 찾게 해주고, **지식그래프는 답까지 가는 경로를 남긴다.**"
  경쟁력은 모델 성능이 아니라 *조직의 지식·관계·맥락 구조를 누가 잘 설계하느냐*.

## 2. 우리 설계와 대조

| | 지식그래프 글 (②구조층) | Nightwish |
|--|------------------------|-----------|
| 출발점 | "지식그래프 ≠ 검색" | **동일** — §1 "AI ≠ 검색, 인덱스 ≠ 인텔리전스" |
| 경로 보존 | "답까지 가는 경로를 남긴다" | 온톨로지 트리·포크·계승(수렴 거부) |
| 출처/근거 | provenance·최신성 | 검증 닻·노드 출처 |
| 신뢰 | 신뢰도 점수가 "**필요하다**"고 *말함* | 허브/권위·스테이킹·검증 게이트로 **구현** |
| 평가·경제 | **없음** | 기여+확신+보상(①시장층) |
| 책임 | 없음 | "사람만 베팅하고 책임진다"(§8.2) |

### 같은 곳
독립적인 방증이다 — 출발점·경로보존·provenance·거버넌스 필요성이 우리와 같은 결.

### 우리가 한 발 더 간 곳 (①시장층)
그의 글은 **②구조**까지("관계 지도를 잘 설계하는 게 경쟁력"). 우리는 그 위에
**①시장**을 얹는다 — *누가 그 구조를 옳다고 판단하고 자기 자본을 걸고 보상받는가.*
그가 "거버넌스가 필요하다"고 선언한 자리를, 우리는 메커니즘으로 채운다.

### 우리가 배울 곳 (정직하게)
**엔티티 정규화**("같은 고객이 여러 이름으로 등장 → 하나의 ID"). 우리는 노드=Q&A로
구조화 비용은 낮췄지만, *동일 개념을 하나로 묶는 entity resolution*은 아직
미해결이다. → 로드맵에 추가(`../roadmap.md`).
