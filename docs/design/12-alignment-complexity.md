# 12 — 정렬 복잡도: LLM Wiki의 벽과 우리의 우회

> **상태:** 핵심 포지셔닝. 노트 11(대조)의 *왜 우리가 다른가*를 복잡도 관점으로 못박는다.
> **한 줄:** *LLM Wiki는 **전역 일관성**을 유지하려다 초선형(≈제곱) 정렬 비용에 막힌다.
> 우리는 일관성을 **포기**하고 **쓰기시점 주소화 + 모순 공존 + 점증 랭킹 + 사람 샤딩**으로
> 정렬을 국소·점증·emergent로 바꾼다.*

## 1. LLM Wiki의 벽 (사용자 직감 = 맞음)

LLM Wiki는 *하나의 전역적으로 일관된 합성물*을 LLM이 유지한다. 그래서:
- 새 원천 1개가 10~15 페이지를 건드리고, **모순 검사**는 본질상 "새 주장 ↔ 기존 모든
  주장" → 누적 **O(N²)**.
- **Lint(전역 점검)** 는 위키가 커지면 한 번에 컨텍스트에 안 들어간다.

⇒ 엄밀히 *지수(2^N)* 는 아니나 **초선형(대략 제곱)**: 내용이 느는 속도보다 **정렬 비용이
더 빨리 는다.** 증거 = gist 댓글들이 실제로 친 벽(single-pass lint 컨텍스트 초과,
ingestion-order bias, lint 배치+스크래치패드, fragmentation wall).

원인: **중앙집중 + 전역 재조정.** 한 작성자(LLM)가 하나의 일관 산출물을 책임 → 일관성은
전역 속성 → 유지도 전역 작업. 매 수정이 잠재적으로 전체를 건드린다.

## 2. 우리의 우회 (네 갈래)

전역 일관성을 **포기**하고 대신:

1. **쓰기시점 주소화 — O(1) dedup.** 같은 개념 = 같은 **slug** 주소. 정체성이 *생성 순간*
   해소돼, 나중에 "중복이냐?"를 O(N²)로 훑지 않는다. (LLM Wiki의 모순/중복 탐지 비용을
   *애초에 만들지 않음.*)
2. **모순 공존 — 전역 병합 안 함.** 충돌은 **정정/다른 답(fork)** 으로 그 노드에 국소적으로
   붙는다. 하나의 진실로 재조정하지 않으니 재조정 비용 0.
3. **재조정 대신 점증 랭킹.** "무엇이 맞나"는 **권위/평가**가 점증적으로 매긴다(메모이즈,
   노트 06). 페이지 재독·재작성이 아니라 점수 전파.
4. **사람으로 샤딩된 판단.** 정렬 노동이 한 LLM의 전역 패스가 아니라, 각자 자기 영역에서
   내리는 국소 판단(각 O(1))의 합. 아무도 그래프 전체를 들 필요 없음.

⇒ **전역 O(N²) 주기 패스 → 국소·점증·emergent.**

## 3. 정직한 단서 (비용은 없앤 게 아니라 *이전*했다)

- 독자는 *단일 합성* 대신 **복수형(forks/variants)** 을 본다 → 트리 + 권위 랭킹으로 완화하나
  인지 비용은 남는다.
- dedup은 slug 주소화에, 채점은 점증 메모이즈에 **계속 의존**해야 한다(전역 재계산으로 새면
  도로 터진다 — 불변식으로 지켜야 함).
- LLM Wiki가 주는 **"전부를 가로지른 한 장짜리 요약"** 은 공짜로 안 나온다 — 필요하면 그건
  여전히 비용.

## 4. 왜 이게 옳은 트레이드인가

**커먼즈(다인 공용)에선 *하나의 강제된 합의* 자체가 틀린 목표다.** 위키피디아 편집 전쟁이
증거. *재조정 강제*를 버리고 *공존 + 랭킹*을 택한 것은 비용 회피이자 **더 옳은 인식론**이다.

> 불변식(깨지면 벽이 돌아옴): ① slug = 쓰기시점 identity, ② 권위/채점은 점증·메모이즈,
> ③ 모순은 병합 말고 공존+랭킹, ④ 수정은 국소(anchored)·append 위주.
