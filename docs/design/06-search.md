# 06 — 검색: 하이브리드 색인 (서비스의 엣지)

> **상태:** 설계 → **구현 완료**(`search.py` + `tree.search`). 특정-개념 질의에서
> 코퍼스 5만 노드까지 **~55µs 평평**(옛 전수조사 대비 **1190×**).
> **한 줄:** *공유 시점에 색인(역색인 + 임베딩)을 만들어 두고, 검색은 일반 검색
> 서비스처럼 싸게. 그 위에 우리만의 엣지 — **권위(안목)·그룹 사적 endorse로 재정렬**.*

---

## 1. 문제 (왜 바꾸나)

기존 `OntologyTree.search`는 **검색 때마다 전수조사**였다:
- 매 질의마다 `nodes.values()` 전체를 돌고, 노드마다 `_subtree_text`로 자손까지
  재귀 연결해 부분문자열을 셌다 → **글 2배 = 검색 2배 느림**(베타에서 51→25 req/s).
- 벡터·임베딩 **전무** → 의미 검색 불가("냉각"↔"쿨링" 못 찾음).
- 쓰기 시점에 **아무 색인도 안 만듦.**

검색은 이 서비스의 **엣지**다. 정공법으로 간다.

## 2. 아키텍처 — 색인은 쓰기 때, 검색은 싸게

```
공유/쓰기(_finalize)                 검색(query)
  └─ upsert(node)                      └─ ① 역색인으로 후보 회수 (O(매칭))
       ├─ 토큰화(CJK: 단어+문자 bigram)      ② 후보를 하이브리드 점수화
       ├─ 역색인 갱신(postings)               lex(BM25)⊕sem(코사인)
       └─ 임베딩 벡터 저장                   ③ 권위·공간 부스트로 재정렬
                                              × authority_in(node, space)
```

### 2.1 어휘 검색 (lexical) — 진짜로 동작하는 코어
- **토큰화:** 소문자화 + 단어 토큰 + **CJK 문자 bigram**(형태소기 없이 한국어 부분일치·재현율 확보).
- **역색인:** `term → {doc_id: tf}`, 문서길이/df 유지.
- **BM25**(k1=1.5, b=0.75): 표준 어휘 랭킹. 질의어가 든 문서만 postings로 회수 →
  **비용 O(매칭 문서)**. 전수조사 제거.

### 2.2 의미 검색 (semantic) — 끼워넣을 수 있게
- **임베더는 LLM처럼 교체형**(`set_embedder`). 프로덕션은 실제 임베딩 모델/API,
  개발·테스트는 **의존성 0 오프라인 결정적 임베딩**(문자 n-gram 해시 → 고정차원 L2정규화).
  파이프라인·랭킹·영속은 동일, 품질만 모델에 비례.
- 어휘 후보군을 **코사인으로 재정렬**(저비용). 순수 의미 회수(ANN)는 후속 과제.

### 2.3 우리만의 엣지 — 권위·공간 인지 랭킹
- 최종 점수 `= 하이브리드_관련도 × (1 + boost·authority_in(node, space))`.
- `authority_in`은 **공통 권위(prior) + 그룹 사적 endorse 오버레이**(노트 05).
  → **같은 질의도 그룹마다 다르게 랭킹된다**(그룹의 사적 평가가 검색을 재정렬).
  일반 검색엔진엔 없는 차별점.

## 3. 통합·생애주기
- 엔진은 트리에 매달림(`OntologyTree._search`). 모든 생성/수정의 단일 길목
  **`_finalize`에서 upsert** → 증분 갱신.
- **지연 빌드:** 인덱스가 없으면 첫 검색에서 1회 전체 빌드, 이후 증분. 트리 재구성(DB
  스냅샷 리로드) 시 새 인덱스가 다음 검색에 다시 빌드 → 쓰기마다 비용 없음.
- 스텁(빈 개념)은 검색 제외(기존과 동일). **스레드 findability:** 자식 hit는
  **최상위 조상(공유 단위)으로 롤업**해 합산 → 기여로도 개념이 검색된다.
- 막(membrane): 후보를 `_visible(space)`로 필터 → 그룹 콘텐츠 비누수.

## 4. 비용
- 질의: **O(질의어 postings + 후보 코사인)** — 글 수 N에 선형 아님.
- 빌드: 로드당 1회 O(전체 텍스트)(지연), 런타임은 증분 O(노드 텍스트).
- 메모리: 역색인 + 벡터(D차원). 벡터 영속은 후속(실모델 재계산 절약).

## 5. 단계
1. `search.py` — `HybridIndex`(토큰화·BM25·벡터·하이브리드) + 단위 테스트.
2. `OntologyTree`에 매달고 `_finalize` 증분 + `search` 위임(시그니처·막 유지).
3. 권위·공간 부스트(엣지) + 빈 질의=권위순.
4. 베타 시뮬로 비용 곡선 검증(초선형 둔화 제거).

## 6. 후속 / 한계
- 실제 임베딩 모델 연결(프로덕션 1줄 plug)·벡터 영속·ANN 순수 의미 회수.
- 형태소 분석기(은전한닢 등) 옵션, 동의어/오타 보정, 하이라이트.
- DB 모드에서 점-조회와 색인 일관성(현재 in-memory `svc.tree` 기준).
