# 25 — 하이브리드 그룹: 사일로 + 렌즈 (노트 05 개정)

> 사용자 지적: *"그룹을 만들고 그룹 오버레이로 보면 기존 자료는 맨 처음에는
> 하나도 안 보여야 하지 않나?"* — 맞다. 점검 중 더 중요한 것도 발견:
> **그룹에서 물은 질문·답이 공용 커먼즈에 생성**되고 있었다(기밀 위반).
> 노트 05의 렌즈 모델을 그룹에 한해 개정한다. 결정: 전부 진행("전부요~").

## 1. 새 의미론 — 세 문장

1. **그룹 공간 = 우리가 만든 것 + 우리가 밟아 들여온 것.** 새 그룹은 빈
   화면에서 시작한다. 공용 노드는 그룹원이 그룹 발자국으로 밟는 순간 이
   공간에 들어온다(들여오기 = 이미 있는 제스처, 새 메커니즘 0).
2. **공용 커먼즈는 사다리의 명시적 계단.** 그룹 검색은 ① 우리 것 → ② "🌐
   공용 커먼즈에서"(배지 달고, 밟으면 들여옴) → ③ 종합 → ④ 생성.
3. **그룹에서 만든 질문·답·페이지는 그룹 소유(기밀 기본).** id는
   `그룹::슬러그`로 네임스페이스되어 공용 주소를 점유하지 않고, 공용 공개는
   **명시적 publish**로만. 본문의 [[참조]]는 여전히 공용 앵커(노트 05 보존).

## 2. 기계 장치 — 읽기 권한과 공간 소속의 분리

- `_visible` (READ): 공용 ∪ 자기 그룹 — **불변**. 공용 노드는 그룹 뷰에서도
  *열람 가능*(공용이니까). 일방향 막도 불변.
- `in_space` (신설): 검색·트리·랭킹·통계·지도 등 **"내 공간" 목록**의 기준.
  공용 뷰=공용 / 그룹 뷰=그룹 소유 + `group_adopted`(그룹 엔진에 발자국 존재).
- 채택 판정(ask 재사용)도 공간 인지: 그룹에선 그룹 발자국이 채택.
- 그룹 endorse의 저자 가드 제거: 자기 공용 글을 자기 그룹에 들여오는 것도
  채택 — 그룹 코인은 자유발행·비태환이라 자기부양 이득이 없다.

## 3. 노트 05에서 무엇이 남고 무엇이 바뀌나

| 노트 05 원칙 | 운명 |
|---|---|
| 그룹 코인 = 자유발행·비태환·단방향(공용 랭킹 불오염) | **불변** |
| 일방향 막(공용은 그룹 것 못 봄) | **불변** |
| [[참조]] = 공용 앵커(스텁 공용 출생) | **불변** |
| 그룹 뷰 = 공용 전체 ∪ 오버레이 | **개정** → 들여온 것만 |
| 그룹 발화 루트 = 공용 개념 | **개정** → 그룹 소유·네임스페이스·publish로만 공개 |

## 4. 검증

- 테스트 **174개**(신규 2 + 의미론 갱신 4): 새 그룹 빈 공간 → 발자국 들여오기,
  그룹 질문 기밀(공용 검색·열람·타그룹 404), 같은 그룹 재질문 재사용, publish
  공개, 참조 스텁 공용 유지, 렌즈 재정렬은 들여온 것 안에서.
- 브라우저 E2E: 빈 그룹 안내 → 🌐 공용 계단 → 밟아 들여오기 → 그룹 질문 →
  공개 버튼 → 공용 검색 기밀 유출 0건. JS 오류 0.

## 5. 함의

B2B 소구("우리 팀의 공간")와 기밀 원칙(결정로그: 기밀 유출=치명적)이 정면으로
선다. 렌즈 모델의 좋은 점(그룹 endorse=재정렬)은 "들여온 것 안에서의 재정렬"로
그대로 살아 있다. 남은 관찰: publish된 노드의 슬러그가 공용 개념과 충돌하는
드문 경우(현재 id 불변 유지) — 실사용에서 재평가.
