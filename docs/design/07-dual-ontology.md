# 07 — 이중 온톨로지: 전역 개념(커먼즈) × 맥락 내 재귀

> **상태:** ⚠️ **UX는 [노트 08](08-one-gesture.md)로 대체됨** — (a)/(b) 두 버튼 분기 폐기,
> 단일 재귀 제스처(가리키기→보기→묻기)로 통합. 아래 기계장치(`anchor`·`unfold`·`promote`·
> `classify`·영속)는 *보이지 않는 기질*로 잔류하며 emergent 승격의 토대가 된다.
>
> 결정 완료(D1=명시적 이중) → 구현 완료(S1·S2·S3).
> **한 줄:** *드래그한 구절은 **(a) 보편 개념(전역 slug·커먼즈)** 이거나 **(b) 이 맥락의
> 하위 펼침(스팬에 앵커된 국소 자식)** 이다. AI가 제안하고 사람이 택한다. (b)는 그 자리에
> **인라인으로 접혀** 재귀로 쌓이고, 합의되면 (a)로 **승격**된다.*

---

## 1. 왜 (관통 질문)

지금까지의 모든 작업(사적/공적 endorse, 검색, stub 채우기, 슬라이딩 패널)은 한 질문의
다른 면이었다 — **"노드·관계가 무엇이고, 의미는 어디에 사는가."** 그 상류 결정이 이것이다.

두 직관이 충돌했다:
- **단어–단어 시멘틱스(개념 그래프):** 전역 개념 노드 + 링크. 커먼즈·dedup. (앞서 채택)
- **문장 속 의미(맥락 재귀):** 본문 텍스트, 의미는 문장 안. 구절을 그 자리에서 Q&A로
  펼치고, 그 답에 또 구절이 생겨 재귀. (나중 깨달음 — 이 시스템의 창립 비전, 노트 02)

결론: **둘 다 진짜다.** 하나를 버리지 않고 **둘을 1급 관계로** 둔다.

## 2. 두 관계 (1급)

| | **(a) 보편 개념 링크 — commons** | **(b) 맥락 내 펼침 — contextual** |
|---|---|---|
| 만들어지는 것 | 전역 개념 노드(slug) + 위키링크 | 스팬에 앵커된 **국소 자식 Q&A** |
| 정체 | 전역 1개(공유·dedup·공용) | 부모 서브트리 소속(맥락별, 중복 허용) |
| 가시성 | 개념=공용(노트 05) | 부모를 따른다(공용/그룹 오버레이) |
| 표현 | **가로 슬라이딩 패널**(개념 순회) | **인라인 접이식 펼침**(그 문장 밑) |
| 예 | "벡터 시계"가 보편 개념일 때 | "이 문장에서 *그게 왜 그런가*"를 더 파기 |

핵심: **(a)는 맥락을 떠나 공유 좌표가 되고, (b)는 맥락에 머문다.** 같은 단어라도 문장마다
뜻이 다르면 (b), 어디서나 같은 개념이면 (a).

## 3. 드래그 흐름 (D2 — 전역화 규칙)

```
본문에서 구절 선택
   └─ AI가 제안:  ◉ 보편 개념(전역 연결)   ○ 이 맥락의 하위 펼침
        (근거 한 줄: "이미 개념 X로 존재" / "이 문장 한정 해설로 보임")
   └─ 사람이 확정
        (a) → expand: 전역 개념 + 위키링크            [기존 경로 재사용]
        (b) → unfold: 스팬 앵커 + AI 답을 인라인 자식으로  [신규]
```

- **승격(b→a):** 국소 펼침이 무르익어 보편 가치가 있으면 전역 개념으로 **승격**한다.
  이는 노트 05의 **"승격=재스테이크"** 와 동일 골격 — 국소에서 전역으로 *가치 누수 없이*.
  방향은 **한쪽(국소→전역)** 만; 전역이 다시 국소로 쪼개지진 않는다.
- 이 한 규칙이 앞서의 긴장(**커먼즈 ↔ 맥락**)을 화해시킨다: *국소로 시작 → 합의 시 커먼즈로*.

## 4. 표현 (D3 — 척추)

- **기본 = 인라인 펼침(transclusion).** (b) 자식은 부모 문장 *아래*에 접이식으로 펼쳐지고,
  그 자식 본문의 구절에 또 펼침이 달려 **재귀로 읽힌다.** "구조 자체가 다음 답"이 화면이 된다.
- **보조 = 가로 슬라이딩 패널.** (a) 보편 개념을 따라갈 때만 오른쪽으로 패널이 쌓인다(현행).
- 그래서 **"부모에서 가지 여러 개"** 문제는 (b)에선 자연 해소된다 — 형제 펼침이 부모 밑에
  중첩될 뿐, 가로 분기 고민이 사라진다. (C-하이브리드 가지-칩은 (a) 패널에만 남는 보조 장치.)

## 5. 스팬 앵커 (빠졌던 핵심)

(b)는 **어느 구절에서 나왔는지**를 정확히 기록한다:
- 자식 노드에 `anchor`(인용 텍스트 + 부모 내 위치) 보존.
- 부모 본문에서 그 구절은 **밑줄/주석 표시**, 클릭하면 인라인 펼침 토글.
- 재독 시 "이 문장의 *이 부분*을 펼쳤다"가 보인다(현재는 위키링크만 덧붙고 흔적이 흩어짐).

## 6. 기존 작업과의 정합 (아무것도 안 버림)

| 기존 | 이중 모델에서의 자리 |
|---|---|
| 다중통화 endorse(노트 05) | 그대로. (b)는 부모 가시성/오버레이 상속, (a)는 개념=공용 |
| 하이브리드 검색(노트 06) | 그대로. (b) 텍스트도 색인·롤업(이미 자식 롤업 있음); 단위가 스팬까지 내려감 |
| 빈 stub AI 채우기 | (a)의 빈 개념을 채우는 것 = 변함없음 |
| 슬라이딩 패널·가지-칩 | **(a) 전용**으로 재배치. (b)는 인라인 |
| 평가=저작, 초안→채택 | 그대로. 승격(b→a)이 채택 게이트와 통합될 후보 |

## 7. 코드 지도 (구현 스케치)

1. **데이터:** `Node`에 `anchor`(부모 스팬: 인용+offset) 추가. (b)는 `CONTRIBUTE`(또는 신규
   `UNFOLD`) + `anchor`. (a)는 현행 `expand`/위키링크 유지.
2. **API:** `POST /api/nodes/{id}/unfold {anchor, question}` — 스팬을 맥락 자식으로 AI 펼침
   (부모 체인 프롬프트 앵커링은 expand의 `_anchor_prompt` 재사용). 드래그 분류용
   `POST /api/classify {span, context}` → AI가 (a/b) + 근거 제안.
3. **검색:** (b) 자식 색인은 현행 롤업으로 자동 포섭; 스팬 하이라이트는 표시층.
4. **UI:** 드래그 팝업에 (a)/(b) 선택(AI 추천 프리셀렉트). (b)는 본문 스팬에 밑줄 +
   인라인 접이식 펼침(재귀). (a)는 현행 패널.

## 8. 단계 (구현됨)

- **S1 ✅:** `Node.anchor` + `/contribute kind=unfold`(스팬 앵커 단일 AI 답) +
  `_node_view`의 unfolds/thread 분리 + 인라인 재귀 UI(드래그 (a)/(b) 버튼, 구절 밑줄,
  `<details>` 블록). 영속(pgstore `anchor` 컬럼 + 마이그레이션).
- **S2 ✅:** `POST /api/classify` — 강신호(기존 commons 개념) + 휴리스틱(짧은 명사구→개념 /
  문장형→펼침), 실 LLM 활성 시 정교화. 팝업이 제안 버튼 강조 + 근거.
- **S3 ✅:** `POST /api/nodes/{id}/promote` — 펼침(b)→보편 개념(a). **재스테이크**: 초안으로
  시작해 채택 게이트를 새로 통과; 부모 스팬에 commons 링크 추가(이중 본성). 일방향.

## 9. 미해결

- (b)의 스팬 앵커가 부모 본문 *편집 후*에도 유지되는가(텍스트 이동/삭제 시 앵커 보정).
- (b) 자식의 검색 단위·권위 부여(스팬 단위 평가까지 갈지).
- 인라인 펼침 깊이가 깊어질 때의 가독성(접힘 기본 + 패널 "펼쳐 보기" 탈출구).
