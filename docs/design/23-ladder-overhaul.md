# 23 — 대대적 개편: 비용 사다리가 곧 화면이다

> 지금까지의 모든 논의(노트 00~22)가 한 문장으로 수렴한다:
> **"재사용 < 종합 < 생성"의 비용 사다리(노트 15·19)를 사용자가 *걷는 화면
> 그 자체*로 만들고, 모델 라우팅도 같은 사다리를 타게 한다.**
> 미션("같은 답을 수천 번 다시 만들게 하지 않는다")이 설명이 아니라 동선이 된다.

## 0. 설계 방향 (수렴 원칙 5)

1. **사다리가 기본 동선** — 질문 하나에 ①기존 답(공짜·검증됨) → ②종합(싼 모델)
   → ③생성(프런티어·쿼터)이 *한 흐름*으로 이어진다. 생성은 바닥이 아니라
   꼭대기(가장 비싼 마지막 계단).
2. **신호는 읽는 자리에서** — 채택·신선도·정정 제기·조건·두루를 검색 결과
   카드에서 바로 본다. 눌러 들어가기 전에 "믿을 만한가"가 보여야 한다.
3. **모델은 작업 난이도를 따른다** — 엮는 작업(종합·요약·분류)은 싼 층,
   새 생성만 프런티어 (노트 19 §1; 노트 20 축 E의 마지막 코드 공백 해소).
4. **판정은 사람, 시스템은 신호만** (제1원리 — 불변).
5. **효율은 상한으로** — 무한 리스트·무한 생성 없음(검색 캡, 생성 쿼터).

## 1. 시스템 개편

| 항목 | 전 | 후 |
|---|---|---|
| **AI 라우팅** | 모든 호출이 단일 `_ai_fn`(프런티어) | **티어드**: `set_cheap_ai(fn)` — 종합(synthesize)·URL 요약·조건 추출·구절 분류는 싼 층(`_cheap_ai`, 미설정 시 폴백), *새 생성*(ask 초안·후속·펼침·스텁 채우기)만 프런티어. 배포: `NIGHTWISH_CHEAP_MODEL`(기본 haiku) 자동 배선, `/api/health`에 `cheap_model` 노출 |
| **검색 응답** | 매칭 전부 반환(무상한 — 결과 노드마다 두루·신선도 계산) | `limit` 파라미터(기본 24, 최대 50) — 계산·페이로드 상한 |
| **생성 응답** | stage만 | `quota_left` 포함 — UI가 "오늘 N건 남음(재사용·검색·종합 무제한)" 표시 |

미션 3대 항목의 마지막 공백이었던 **과잉 프로비저닝 제거(노트 20 축 E)**가 이로써
코드가 됐다: 검색·평가 = LLM 0 / 종합 = 싼 층 / 생성 = 프런티어+쿼터.

## 2. 화면(UX) 개편 — 사다리 동선

- **입력 한 줄, 계단 세 개.** 플레이스홀더부터: *"기존 답(공짜)부터 찾고, 없으면
  종합, 그래도 없으면 생성"*. 주 버튼 = **🔎 기존 답 찾기**(1계단), **✨ 새 답
  생성**은 보조 버튼 + 결과 *아래* 마지막 계단으로 강등.
- **재사용 리드 배너** — 결과 상단에 *"♻️ 기존 길 N개 (사람이 가려낸 답 M개) —
  재사용은 공짜이고, 이미 검증된 답입니다."* 결과 0이면 *"당신이 첫 걸음"*.
- **결과 카드 신호 강화** — 채택/초안 + 🟡/🔴 신선도 + ⚔️ 정정 제기 + 적용 조건
  칩(2개까지) + 두루 N(접힌 경우만) + 👣·권위. **채택 우선 정렬 토글**.
- **2계단(종합)**: 기존 "위 N개를 종합해서 답변할까요?" 유지 — 이제 싼 층에서 돈다.
- **3계단(생성)**: 결과 아래 "위 답들로 부족하면 — ✨ 새 답 생성". 생성 성공 시
  *"오늘 N건 남음"* 토스트(쿼터 설정 시), 429는 안내문으로.
- **existing 배너 강화**: *"♻️ 같은 질문에 사람이 가려낸 답(권위 최고본)이 이미
  있어 재사용합니다 — 생성 0원."*

## 3. 검증

- 테스트 **167개** 통과(신규 3: 티어 라우팅이 종합만 타는지 / 검색 캡 / 쿼터 잔량).
- 시뮬 재실행: 11개 페르소나 판정 불변(10 ✅ · 정정자 ⚠️=설계 귀결), 부하 p95<20ms.
