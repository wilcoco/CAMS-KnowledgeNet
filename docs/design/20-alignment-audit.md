## 0. 취지 재확인 (정본)

- **미션:** AI 비효율 3종 — **중복 생성 · 과잉 프로비저닝 · 무축적** — 을 개선.
  "같은 답을 수천 번 다시 만들게 하지 않는다 — 한 번 만들어, 사람이 가려내고,
  모두가 재사용한다."
- **제1원리(노트 00):** 답설야중거 — 많이가 아니라 두루, 내 자취가 뒷사람의 길.
- **정렬(노트 14·15):** 사람=판단, AI=횃불. 재사용 위에 사람 4겹(기여·판단·대안).

## 2. 이번 감사로 고친 것 (구현·테스트 통과 158개)

1. **교정답 우선 노출 (노트 18 P0 — 사례의 심장).** `ask`의 existing 경로가
   '먼저 채택된 표준답'이 아니라 **같은 질문 군집(원답+스레드) 전체의 권위
   최댓값**을 돌려주도록 못박음. 회귀 테스트: *표준답이 먼저 채택돼 있어도
   더 두루 밟힌 정정(fork)이 뜬다.*
2. **신선도 (노트 18 P1 — 지식은 썩는다).** `freshness_of`(🟢≤90d/🟡≤1y/🔴):
   시계 자동·입력 0, 권위에 *완만한* 계수(stale ×0.9 — tie-breaker급), UI 배지
   + stale 채택본에 "아직 유효한가요?" 재검 넛지. **자동 폐기 없음 — 판정은 사람.**
3. **로드맵 현행화.** `roadmap.md`가 옛 풀스펙 트랙 기준이라 새 독자를 오도
   (이번 컨테이너 재생성 때 실제 혼란 발생) → 트랙 배너로 현행 할 일 위치를 명시.

## 3. 남은 보완점 (우선순위)

1. **실사용 점화 0 — 최대 공백.** 시뮬레이션(23인)은 통과했으나 *실제 소그룹이
   한 바퀴 돈 적이 없다.* 노트 15 "점화=소그룹"이 아직 이론. → **다음 한 걸음:
   본인 팀 하나로 실측** (질문 10개·발자국·정정 1건이면 충분).
2. **링 허브 인플레이션 + 스텁-링크 파밍** (결정로그 미해결 2건) — 읽기 렌즈가
   못 누르는 적립단. → 노트 13 §7 3단계 *적립단 할인* + 스텁 대상 링크 감액.
3. **노트 18 P2·P3** — 조건 패싯(AI제안+탭확인)·반증 유도 플레이스홀더.
4. **티어드 라우팅(노트 19)** — 종합→싼 모델 분리 + 새 생성 무료 쿼터. LLM
   실연동(Railway) 시점에 `set_ai` 옆에 `set_cheap_ai` 하나면 됨.
5. **자동 자기발자국(노트 13 잔여)** — 저자=첫 밟은 이 자동 기록.
6. **신선도의 '갱신' 동선** — 현재 재검 넛지는 정정으로만 리셋. 가벼운 "확인함
   (시계 리셋)" 제스처는 노동화 금지선과 저울질 후 결정.

## 4. 한 줄 결론

**세 진단 중 둘(중복 생성·무축적)은 코드가 미션을 정확히 살고 있고, 사람-판단
층은 시뮬레이션으로 검증까지 됐다.** 남은 어긋남은 (a) 과잉 프로비저닝 항목이
설계에만 있는 것, (b) 모든 검증이 아직 시뮬레이션인 것 — 다음 한 걸음은 기능이
아니라 **실제 소그룹 한 바퀴**다.
