# 05 — 사적/공적 지식의 구별과 연동 (다중통화 endorse)

> **상태:** 합의 완료(사양 고정), 구현 착수.
> **한 줄:** *개념(slug)은 항상 공용 commons. 사적인 것은 그 위에 얹는 **층(layer)**.
> 가치(endorse)는 공통 코인 1개 + 그룹별 사적 코인의 **다중통화**, 전부 **단방향**.*

---

## 1. 문제

`space`(공간) 모델이 두 가지를 한 덩이로 묶고 있었다 — **개념의 정체**와 **내용의 공개범위**.
그래서 "개념을 사적으로" 만들면:

- 전역 `slug` 주소를 사유화(squatting) → 남들은 그 개념을 **영영 못 만듦**
- 같은 개념이 공간마다 갈라짐(**이빨 빠짐**)
- 자동추출 stub(`[[...]]`)이 *언급한 노드의 space*로 태어나 **보편 개념이 사유화**됨
  (`tree.py`의 `space=node.space` 한 줄이 씨앗)

근본 원인: **정체(identity)와 가시성(visibility)을 직교시키지 못함.**

## 2. 절단선 — 무엇이 사적화될 수 있나

| 행위 | 노드 유형 | 본문 출처 | 사적화 |
|---|---|---|---|
| AI에게 묻기 (`/api/ask`) | ROOT | **AI** | ❌ 공용 |
| 연결 개념 (`/api/expand`) | ROOT | **AI** | ❌ 공용 |
| `[[ ]]` 자동추출 | STUB | — | ❌ 공용 |
| `create_node` (UI 미연결, API 전용) | ROOT | 사람 | ❌ 공용 고정 |
| 보강·정정·계승 (`contribute`) | child | 사람 | ✅ 가능 |
| 후속 질의/답 (`queries`) | child | 사람/AI | ✅ 가능 |
| 평가 (`endorse`) | (링크) | 사람 | ✅ 가능 |

**원칙:** *빈 개념 정리 = AI = 공용. 사람이 그 위에 얹는 모든 것(보강·정정·후속·평가) = 사적 가능.*

- 사람이 슬러그를 **직접** 채우는 UI 경로는 **없다**(전 프론트엔드 확인). `create_node`는 API 전용 고아 엔드포인트.
- "사적 ROOT"은 성립 불가 — 내용이 사적인 순간 그건 *공유 개념*이 아니라 *그 개념에 대한 누군가의 층*이다.
- 따라서 **ROOT 생성 경로는 space를 무시하고 public 고정**, **child만 space 수용**, 자동추출 stub도 **public 출생**.

## 3. 가치 모델 — 다중통화 endorse

공적/사적 endorse 관계를 통화로 정리한다.

- **공통 코인 1개** = 서비스 전체 commons endorse → 모두의 **발견/검색 기준선(prior)**.
- **그룹별 사적 코인** — 결정 3개:
  1. **비호환(incommensurable):** 그룹 코인은 그룹끼리 안 보이고 환산도 없다. (서브레딧 karma처럼)
  2. **자유발행(free issuance):** 그룹이 내부 scrip을 자유 발행. 공적 가치에 안 닿으므로 희소성 불필요.
  3. **그룹 내부 집계:** 그룹 endorse는 그룹 코인을 소비하고 **그룹 안에서만** 집계·가시. 공통 권위엔 무영향.

### 불변식 (Invariants)

- **단방향(one-way):** 그룹은 공통을 *읽고 참조*한다. 공통은 그룹을 *무시*한다.
  (코드의 일방향 막 `tree._visible`와 동형: `public ∪ 그 그룹`만 가시.)
- **비태환(non-convertible):** 그룹 코인 ↔ 공통 코인 교환 없음. → 내부에서 찍은 코인으로 **공적 권위를 살 수 없음**(시빌·게이밍 구조적 차단).
- **승격=재스테이크(re-stake, not convert):** 사적 endorse가 공개로 승격될 때 그룹 코인이 공통 코인으로 *변환되지 않는다*. 공통 코인 보유자가 **새로 스테이크**해 공적 endorse한다. 사적 endorse는 *지명/신호*일 뿐. → 사적→공적 가치 누수 차단.

### 검색/발견 시맨틱 (결정 #3)

> 그룹 안에서도 **공통 콘텐츠 + 공통 endorse를 prior**로 랭킹한다.
> 그 위에 **그룹 endorse가 그룹 코인으로 국소 재정렬**한다(그룹 내부 순위만 변경).

즉 한 개념의 그룹 내 점수 = `공통_권위(prior) + 그룹_endorse(그룹 전용 오버레이)`.
공통 권위는 항상 발견의 바닥이라 그룹이 commons에서 떨어져 나가지 않는다(파편화 차단).

## 4. 왜 두 함정을 동시에 피하나

- **시빌/게이밍:** 비태환 + 자유발행이라 사적 코인으로 공적 권위 매입 불가.
- **파편화/필터버블:** 공통 prior가 항상 검색 베이스라인이라 그룹이 commons에 묶여 있음.

→ "개념=공용" 철학과 끝까지 일관.

## 5. 코드 매핑 (구현)

현재 `tree.scoring`은 **단일 전역** `ScoreEngine`(`scoring.py`). 이를 **space로 파라미터화**한다.

1. **ROOT 경로 public 고정** — `ask`/`expand`/`create_node`의 `add_root(... space=...)`를 `space="public"` 고정. 자동추출 stub(`tree.py`의 `space=node.space`)도 `"public"`.
2. **`create_node` stub 승격 500 수정** — 기존 노드가 stub이면 `add_root`가 `OntologyError`를 던져 500. `expand`처럼 stub 삭제 후 승격(또는 400 처리).
3. **다중통화 스코어링** — 공통 = `public` 원장, 그룹 = `(space)` 원장. `endorse`는 자기 space의 코인을 소비, 그 space의 `ScoreEngine.link`만 갱신.
4. **검색 랭킹** — `authority(node, space)` = `공통_authority(prior) + 그룹_authority(space)`. 단방향: 그룹 점수는 공통을 읽되 공통 점수엔 안 더해짐.

> 가시성(`_visible`)·child의 `parent~seq` 키는 이미 충돌이 없어, 사적 오버레이는 데이터 모델상 곧장 동작한다.

## 6. 참조 사례 (벤치마크)

| 계열 | 사례 | 배울 점 |
|---|---|---|
| 한 그래프·다른 시드 | Personalized PageRank / TrustRank, EigenTrust, PGP Web-of-Trust vs CA | 공적/사적 = 같은 그래프를 두 시드(전역/그룹)에서 평가 |
| 다층 스코프 평가 | Wikipedia WikiProject 등급, Goodreads/Letterboxd | 한 항목에 전역 + 그룹 + 개인 평가층, 뷰어 기준 머지 |
| commons+팀공간+승격 | **Stack Overflow for Teams**, 동료심사→게재→피인용 | 별도 평판 원장 + 승격(declassify) 생애주기 |
| 다중통화 | 서브레딧 karma, 보완화폐(LETS), 로열티 마일 | 비호환 scrip + 공통 참조, **태환 다리 = 공격면** |

## 7. 미해결 / 위험

- 그룹↔그룹은 완전 비호환·상호 불가시(확정). 그룹 *간* 협업이 필요해지면 별도 합의 통로 필요.
- 승격(declassify)의 트리거·권한(누가 사적 endorse를 공적으로 지명하나)은 초안→채택 게이트와 통합 여부 미정.
- 그룹 코인 자유발행의 *남용*은 그룹 내부 문제로 격리됨(공적 무영향)이나, 그룹 내 신뢰 관리는 그룹 몫.
