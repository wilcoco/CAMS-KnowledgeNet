# 19 — 초기 비용과 BYOK: 재사용이 비용을 줄인다

> 장애요소: 사용자가 여기서 *작업*하려면 LLM이 필요한데 — 자기 키(BYOK)를
> 가져오게 하거나 우리가 고가 API를 연동해야 한다. **초기 비용을 어떻게 작게 두나.**
>
> 답: 우리 제품의 본질은 *생성*이 아니라 **재사용**이라, 일반 AI 앱보다 비용 문제가
> 작다. 비싼 칸(생성)만 게이팅하고 싼 칸(재사용·평가·종합)은 무료로 연다.

---

## 1. 비용 사다리 (질의 1건당)

| 행위 | LLM 비용 | 처리 |
|---|---|---|
| 검색·읽기·평가(발자국) | **≈0** | BM25 + *쓰기 시점 1회* 임베딩. 질의 시 LLM 호출 없음 |
| 종합(synthesize) | **작음·1회·재사용됨** | 기존 본문을 엮는 *쉬운* 작업 → 싼/소형 모델로 충분. 좋다고 판정되면 노드로 굳어 다음엔 0 |
| 새 초안 생성(novel) | **큼·드묾** | 프런티어 모델. *진짜 새 질문*일 때만 |

> 핵심: **셋을 같은 모델·같은 권한으로 묶지 마라.** 묶으면 모든 질의가 프런티어
> 생성 비용을 무는 *일반 AI 앱*이 된다. 분리하면 한계비용이 "진짜 새 질문" 비율에만
> 묶이고, 그 비율은 미션상(덜 쓰고 더 나은 지식) 커먼즈가 쌓일수록 줄어든다.

---

## 2. 초기 비용을 낮추는 레버 (우선순위)

1. **재사용을 기본 동선으로 — 생성률 자체를 떨군다.** 물으면 기존 노드/종합을 먼저
   보여주고(설계됨: `ask`의 `stage:"existing"`), 새 생성은 *정말 없을 때만*. 커먼즈가
   클수록 질의당 생성 비율↓. = 미션과 비용절감이 같은 방향.
2. **작업별 모델 티어링.** 종합·요약 = 싼 모델(Haiku급 또는 자체 호스팅 소형 오픈모델),
   프런티어 = *드문 새 생성*에만. 임베딩은 매우 싸고 쓰기 1회뿐 → 검색은 사실상 LLM 0.
3. **비싼 칸만 게이팅 = 무료 경험은 키 없이.** *(✅ 쿼터 구현 — `NIGHTWISH_ASK_QUOTA`, 노트 22 §3)* 읽기·검색·평가·종합(싼 모델)은 **키 없이
   무료**. **새 초안 생성**만 → ① 하루 N건 무료 쿼터 → ② 초과 시 BYOK 또는 ③ 소그룹
   공동 예산. 첫 경험에 키 입력 벽이 없고, *생성 천장에 부딪히고 이미 가치를 본 사람*
   에게만 키를 요청(BYOK 온보딩 마찰을 뒤로 미룸).
4. **종합 결과를 노드로 캐싱 = 비용 분할상환.** 한 번 종합해 좋다고 판정된 답은 노드로
   남아 다음 사람은 0으로 재사용. "한 번 지불, 여러 번 사용".
5. **소그룹 점화와 결이 맞음.** 인터넷 규모 생성을 서빙할 필요 없음 — 활성 소그룹 수만큼만
   비용. 한 팀이 키 하나 공유/소액 예산 풀링이 자연스럽다.

---

## 3. ⚠️ 무료 LLM 티어 함정 (결정로그에서 재확인)

무료 tier는 보낸 데이터를 **학습에 쓸 수 있음** → *기밀 업무지식 유출* 위험(치명적).
데모/MVP엔 OK, **실작업엔 no-training 보장 유료 종량제나 자체 호스팅**으로. 다른 벽:
rate limit, SLA 없음, ToS 상업 제한.

---

## 4. 권위/허브는 토큰이 아니다 (종합의 토큰 경계)

종합 시 "답변자 허브·권위도 넣어 답하면 좋겠다 → 토큰 폭발?" 우려에 대한 결정:

- **권위/허브는 프롬프트에 *붓는* 데이터가 아니라, 무엇을 넣을지 *고르고*·신뢰도 순으로
  *세우는* 외부 신호다.** 계산은 스코어링 엔진(특허 알고리즘)이 *수치로*, LLM 바깥에서.
- LLM엔 **추려진 상위 K개 본문 + 노드당 한 줄 가중치 태그**(예: `[권위 8.2·검증자 5]`)만.
  토큰은 인구 N이 아니라 **K에 묶임**(예: 5×300 ≈ 1,500 고정).
- "답변자 누구·검증자 수" 풀 정보는 **UI가 📚 근거 옆에 렌더링**(토큰 0).
- = 휘발성 문서(노트 18)의 "평가는 모델 바깥 층2에서" 와 동형. 강점: 신뢰도 추론을
  LLM 토큰으로 비싸게 하지 않고 그래프에서 싸게 계산해 *증류된 결과만* 넘긴다.

---

## 5. 추천 정책 (한 줄)

> **무료 기본 = 재사용·평가·종합(싼 모델, 키 불필요). 게이팅 = 새 생성만(소량 무료
> 쿼터 → BYOK/그룹 풀링).** 한계비용은 "진짜 새 질문" 비율에 묶이고, 그 비율은 시간이
> 갈수록 준다.

구현 유리점: `set_ai(fn)` 추상화로 제공자·모델을 코드 변경 없이 교체 — **가장 싼 걸로
시작 → 나중에 교체**. (구현 시 티어드 라우팅: 종합→싼 fn / 새 생성→프런티어 fn,
무료 쿼터 카운터, BYOK 키 보관은 사용자별 암호화.)
