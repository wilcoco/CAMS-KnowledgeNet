# 참조 — "LLM 개선의 휘발성과 외부 지식층" (사례 문서)

> 출처: 사용자 업로드(2026-06). claude-monitor → statusline 교정 사례로 *대화 중
> 개선이 모델 안에선 휘발하고, 외부 지식/평가 층에서 포획·전파된다*를 논증.
> **우리 미션·노트 12·13·15의 정확한 외부 검증**이라 보존.

## 사례 (1장)
"Claude Code 사용량을 정확히 보고 싶다" →
① 표준답(claude-monitor 설치) → ② 검증실패(95% 빨강 vs 공식 3%) →
③ 원인(로컬 로그 역산 → 가짜 천장) → ④ 교정(공식 `rate_limits` statusline).
**교훈: 표준답 ≠ 최선답 / 개선은 표준답→검증→교정 루프에서 나온다.**
그러나 ④는 대화가 끝나면 모델 안에서 휘발 — 다음 사람은 다시 ①부터.

## 세 개의 층
- **층1 모델 가중치** — 느림·집단·실시간 안 바뀜. *개선이 여기서 휘발.*
- **층2 외부 지식/평가** — 빠름·즉시 전파. **★ 휘발성을 잡는 곳**(RAG·KB·평가).
- **층3 피드백→다음 배치** — 느린 집단 평균. 개별 통찰이 즉시가 아님.
> 정답은 층3(재훈련)이 아니라 **층2.** 다만 그 진짜 가치는 저장이 아니라
> **"무엇이 좋은 교정인가 평가·랭킹·맥락조건화·갱신"** 에 있다.

## 우리 설계와의 대조 (= 외부 검증)

| 문서 | Nightwish |
|---|---|
| 개선은 층1에서 휘발 | 미션의 *무축적* 진단 |
| 포획은 층2(외부 지식/평가) | **우리가 그 층2** — 검색-재사용 + `/api/synthesize` |
| 표준답 ≠ 최선답 | *AI 초안 미판단 → 발자국이 가려냄* |
| 표준답→검증→교정 루프 | *fork(정정)→발자국→채택* (시뮬: 정정이 표적 8.0 역전) |
| 난제=교정의 평가·랭킹 | *권위/안목* |
| **= hub-authority의 LLM 재림** | **코어가 문자 그대로 KR 10-0913256 hub-authority** (노트 13) |

→ 글의 결론("심장은 answer-authority 평가 = hub-authority 재림")이 우리 설계의
정확한 외부 검증. 우리는 그 심장을 *2005년 특허 원본*으로 구현했다.

## 이 글이 짚은 우리의 빈칸 2개 (로드맵 후보)

1. **맥락 조건화** — 교정엔 *적용 조건*이 붙어야("statusline은 Pro/Max 한정").
   우리 *전제(prerequisite) 릴레이션*·그룹층이 근접하나 **노드/교정에 명시적
   *조건 태그*** 는 없음. → 후보: 답/정정에 `조건`(레이어/버전/환경) 메타.
2. **시점 부패·신선도** — 지식은 썩는다(공식 API 나오면 비공식 경로 deprecated).
   *정정-환수*는 토대이나 **신선도/만료 신호**("2026-06 기준", stale 표시)는 미구현.
   → 후보: `answered_at` 기반 신선도 배지 + 오래된 채택답 재검 넛지(=LLM Wiki Lint의
   우리식 — 사람이 갱신, AI는 후보만 제시).
