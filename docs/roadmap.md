# 실행 로드맵 (Roadmap)

설계 정본 §10(미해결 과제)을 **실행 항목**으로 전개한다. 우선순위 순.
각 항목은 "왜 / 무엇을 / 완료 기준(DoD)"으로 적는다.

---

## P0 — 검증 닻을 가진 첫 노드 (가장 먼저)

**왜.** "부가가치=동의"의 순환은 순수 의견 도메인에서 닫히지 않는다(폰지/담합
의심). 외부 현실(ground truth)만이 닻이다. → 첫 노드는 의견이 아니라 **검증
가능한 현실 문제**여야 한다.

**무엇을.**
- Json의 **제조 회사 실제 과제 하나**(반복 불량 1건: 예 — 특정 사출조건에서의
  웰드라인/싱크마크)를 트리의 첫 루트 노드로.
- 답의 참/거짓을 **수율·물성 측정**으로 판정 (동의가 아니라 물성으로).
- 채택 보상 포인트 → 그 포인트로 추가 지적노동 구매 → 한 바퀴 회전.

**완료 기준.** 실제 공장 지표(수율 Δ 또는 불량률 Δ)가 노드 채택 전후로 측정되어
원장에 기록됨. 이론이 실증으로 전환된 첫 사례.

> **✅ 메커니즘 구현됨(MVP):** `verification.py`(측정→검증)와
> `Economy.distribute_dividend(is_verified=...)`(검증된 가지에서만 배당)로 닻을
> 코드화. 데모: `examples/verified_wheel.py` (불량률 8%→2% 측정 후에야 배당 개통).
> **남은 실물 작업:** `route_to_human_fn`을 실제 사내 엔지니어로, 측정값을 실제
> 공장 데이터로 연결 (P3).

## P0 — 부트스트랩 / 첫 카토 온보딩

**왜.** 시뮬레이션이 노출한 진짜 병목(§7.2)은 "흔한 지식 수집"이 아니라
**"희소 암묵지 보유자의 온보딩"**이다. 포인트에 아직 가치가 없는 초기에 은퇴
직전 장인을 무엇으로 들이는가.

**세 후보 경로 + 평가:**

| 경로 | 장점 | 단점 | 권고 |
|------|------|------|------|
| ① 카토 본인 참여 | 가장 깨끗, 본인이 배당 수령 | 부트스트랩(유인) 선결 필요 | 중기 목표 |
| ② Json 대리 형식화(현금) | 부트스트랩 우회, 즉시 가능 | 카토는 시스템 배당 못 받음, 기여자=Json | **초기 현실해** |
| ③ 일반 원리만 | 법적 안전 | 진짜 핵심(손끝 지식) 못 끌어냄 | 보조 |

**유력 카드(권고):** Json의 제조 회사가 **첫 실수요자**. 회사 과제를 올리고 현금
+포인트 혼합 보상으로 사내·은퇴 장인을 ② 경로로 끌어들임 → 포인트가 현실 제조
문제 해결에 닻 → 가치 자생 시작 → 이후 ①로 전환.

**완료 기준.** 한 명의 실제 암묵지 보유자가 노드 1개 이상 기여(②라도), 그 노드가
P0 검증 닻 노드와 연결되어 물성으로 검증됨.

## P1 — 화폐공학 (정직한 균열 3종, [critique](critique.md)와 연동)

1. **순환 정의 / 제로섬.** 배당이 같은 포인트면 외부가치 유입 없이 제로섬.
   - 닻: **노동 유입**(포인트로 지적노동 구매) + **온톨로지 외부 실용가치**(P0).
   - 작업: 포인트↔현금/노동 환율의 *내부 가격발견* 메커니즘 설계.
2. **UBI 인플레이션.** 끝없는 발행 → 단위가치 희석.
   - 작업: **소각/회수 싱크** 파라미터화 (`economy.Economy.burn_rate` 이미 존재).
     "죽지 않는 가지"에 영구 잠긴 포인트의 회수 정책 결정(유동성 영구잠김 위험).
   - **✅ 구현됨(MVP):** `reclaim_dormant`/`restore_on_revival` — 잠긴 포인트를
     소각 않고 유동성 풀로 환원, 부활 시 복원 + 발견 보너스 (가지는 살리되 유동성은
     마르지 않게). 남은 것: 자동 회수 트리거·풀 운용 정책.
3. **스테이킹 수익률 vs 노동 구매력 균형.** 묶기만 해도 불어나면 자본축적 동학.
   - 작업: 배당률(`dividend_rate`) 상한 + 기여 없는 순수 보유의 수익률 0 수렴 규칙.
   - **✅ 구현됨(MVP):** 배당 **시간붕괴**(`distribute_dividend(ages=, half_life=)`)로
     갱신 안 된 지분의 수익률이 0으로 수렴. 남은 것: "기여 갱신" 이벤트와 age
     리셋 연동.

**미결 정책 결정(거버넌스 필요):** 포인트의 **외부 환전 허용 여부.**
열면 투기·식민화(트로츠키), 닫으면 노동유인 약화. → AskUser 대상.

## P1 — 거버넌스 (그람시/트로츠키 급소)

**급소.** "가치 원천을 동의에 두고 그 동의 생산 규칙을 누군가 쥐면, 그 규칙
제정자가 새 지배계급이 된다." 발행 규칙·"기여" 정의·AI 분류기 통제권이 권력.

**작업:**
- 규칙 변경의 **다자 합의 절차**(단일 관리자 금지). 규칙 자체를 트리의 메타-노드로.
- **라우팅 반-마태효과:** 포인트 실린 질문이 늘 상위 허브에게만 가지 않도록 신규·
  잠복 가지로의 분산 쿼터. (현재 `tree.Action.POINTER`/dormant 메뉴가 토대.)
- 관료화 방지: 규칙 관리자의 임기·교체·투명 로그.

**✅ 구현됨(MVP):** `governance.Governance` — **사전공약**으로 분권을 코드에 못박음.
부트스트랩 동안만 관리자 단독 변경 가능, 참여자 N명 도달 시 규칙변경권이 합의체
과반 승인으로 **자동 이전**(`Phase.BOOTSTRAP → DECENTRALIZED`), 모든 변경 로그화.
남은 것: 합의체 선출 규칙·반마태 라우팅 쿼터.

## P3 — 프로덕션 격상 (MVP → 실서비스)

현재 MVP는 메커니즘 증명용 인메모리 구현. 실서비스로 가려면:

- 영속성(노드/원장 DB), 동시성·정합성(스테이킹·배당 원자성).
- 실제 검색(① 단계 임베딩/리트리버) + 실제 LLM(② 단계) 연결.
- 정체성·시빌 저항(동의 담합 = 시빌 공격의 경제 버전).
- 감사 가능성: 모든 평가가 **재현·감사 가능**해야 (네이버 블랙박스의 정반대가 정체성).

## 의존 순서 요약

```
P0(검증 닻 노드) ──┐
                   ├─→ 첫 바퀴 실증 ──→ P1(화폐공학·거버넌스) ──→ P3(프로덕션)
P0(카토 온보딩) ──┘
P2(법무)  ── 병렬, 환전·기여 정의 결정 전 선행
```

> 한 줄: **먼저 공장의 불량 하나를 트리에 올려 물성으로 검증하라.** 그 한 바퀴가
> 돌면 화폐도 거버넌스도 비로소 닻을 얻는다.
